# API Reference

Base URL: `http://localhost:8080` (development) — change in production.

All authenticated endpoints require the header:

```
Authorization: Bearer <access_token>
```

Interactive documentation generated by FastAPI is available at:

- Swagger UI: `http://localhost:8080/docs`
- ReDoc: `http://localhost:8080/redoc`
- OpenAPI JSON: `http://localhost:8080/openapi.json`

The schemas referenced below are defined in `app/schemas/` and reflect the
exact field names and types returned by the live service.

## Authentication

All routes are mounted under `/api/v1/auth`.

### Register

```http
POST /api/v1/auth/register
Content-Type: application/json

{
  "email": "you@example.com",
  "password": "supersecret123",   // min 8, max 128
  "full_name": "You"              // optional
}
```

Returns `201 Created` with a token pair:

```json
{
  "access_token": "eyJ…",
  "refresh_token": "dGhpcyBpcyBhIHJlZnJlc2g…",
  "token_type": "bearer"
}
```

The user is immediately active. Email verification is not yet implemented.

### Login

```http
POST /api/v1/auth/login
Content-Type: application/json

{ "email": "you@example.com", "password": "supersecret123" }
```

Returns `200 OK` with the same token pair shape as register.

### Refresh

Rotates both tokens: the old refresh token is revoked, a new pair is issued.

```http
POST /api/v1/auth/refresh
Content-Type: application/json

{ "refresh_token": "dGhpcyBpcyBhIHJlZnJlc2g…" }
```

Returns `200 OK` with a new token pair. Reusing the old refresh token returns
`401 Unauthorized`.

### Logout

```http
POST /api/v1/auth/logout
Content-Type: application/json

{ "refresh_token": "dGhpcyBpcyBhIHJlZnJlc2g…" }
```

Returns `204 No Content`. The refresh token is marked revoked; the access
token remains valid until it expires (30 minutes by default).

### Me

```http
GET /api/v1/auth/me
Authorization: Bearer <access_token>
```

Returns the current user:

```json
{
  "id": "uuid",
  "email": "you@example.com",
  "full_name": "You",
  "is_active": true,
  "is_verified": false,
  "created_at": "2026-06-21T12:00:00Z"
}
```

## Mailboxes

All routes require authentication. Mounted under `/api/v1/mailboxes`.

### Create mailbox

```http
POST /api/v1/mailboxes
Authorization: Bearer <access_token>
Content-Type: application/json

{
  "email_address": "me@gmail.com",
  "password": "<app-password>",
  "imap_host": "imap.gmail.com",
  "imap_port": 993,             // default 993
  "imap_username": null,        // optional; defaults to email_address
  "is_enabled": true            // default true
}
```

The IMAP password is encrypted at rest (Fernet) before storage. Returns
`201 Created`:

```json
{
  "id": "uuid",
  "email_address": "me@gmail.com",
  "imap_username": "me@gmail.com",
  "imap_host": "imap.gmail.com",
  "imap_port": 993,
  "is_enabled": true,
  "health_status": "unknown",
  "last_sync_at": null,
  "last_error_at": null,
  "last_error_message": null,
  "created_at": "…",
  "updated_at": "…"
}
```

### List mailboxes

```http
GET /api/v1/mailboxes?limit=50&offset=0
Authorization: Bearer <access_token>
```

Returns `200 OK`:

```json
{
  "items": [ MailboxResponse, … ],
  "limit": 50,
  "offset": 0
}
```

`limit` must be in `[1, 100]`.

### Get mailbox

```http
GET /api/v1/mailboxes/{mailbox_id}
Authorization: Bearer <access_token>
```

Returns `200 OK` with a `MailboxResponse`. `404 Not Found` if the mailbox
does not belong to the caller (or does not exist).

### Update mailbox

```http
PATCH /api/v1/mailboxes/{mailbox_id}
Authorization: Bearer <access_token>
Content-Type: application/json

{
  "password": "<new-app-password>",
  "is_enabled": false
  // all fields optional; only those provided are updated
}
```

Returns `200 OK` with the updated `MailboxResponse`.

### Test IMAP connection

```http
POST /api/v1/mailboxes/{mailbox_id}/test-connection
Authorization: Bearer <access_token>
```

Attempts a real IMAP login using the stored credentials. Returns
`200 OK`:

```json
{
  "success": true,
  "message": "Connection successful",
  "health_status": "healthy",
  "mailbox": { MailboxResponse }
}
```

`success` is `false` and `health_status` is `error`/`degraded` on failure;
`message` contains the IMAP server's error in that case.

### Delete mailbox

```http
DELETE /api/v1/mailboxes/{mailbox_id}
Authorization: Bearer <access_token>
```

Soft-deletes the mailbox by setting `deleted_at`. Returns `204 No Content`.
Existing `EmailEvent` rows are retained; the mailbox is simply excluded from
future polls.

## Webhooks

All routes require authentication. Mounted under `/api/v1/webhooks`.

### Create webhook

```http
POST /api/v1/webhooks
Authorization: Bearer <access_token>
Content-Type: application/json

{
  "url": "https://myapp.com/hooks/email",
  "name": "My App",                         // optional
  "event_types": ["email.received"],        // default ["email.received"]
  "is_enabled": true                        // default true
}
```

Returns `201 Created`:

```json
{
  "id": "uuid",
  "url": "https://myapp.com/hooks/email",
  "name": "My App",
  "secret_prefix": "whsec_abc123",
  "is_enabled": true,
  "event_types": ["email.received"],
  "created_at": "…",
  "updated_at": "…",
  "secret": "whsec_abc123…full-secret…"
}
```

> **Save `secret` immediately.** It is shown only on create and rotate. If
> lost, call `POST /webhooks/{id}/rotate-secret` to issue a new one.

### List webhooks

```http
GET /api/v1/webhooks?limit=50&offset=0
Authorization: Bearer <access_token>
```

Returns `200 OK` with `WebhookResponse` items (no `secret` field).

### Get webhook

```http
GET /api/v1/webhooks/{webhook_id}
Authorization: Bearer <access_token>
```

Returns a `WebhookResponse`.

### Update webhook

```http
PATCH /api/v1/webhooks/{webhook_id}
Authorization: Bearer <access_token>
Content-Type: application/json

{
  "url": "https://…",
  "name": "…",
  "event_types": ["email.received"],
  "is_enabled": true
  // all fields optional
}
```

Returns `200 OK` with the updated `WebhookResponse`.

### Rotate signing secret

```http
POST /api/v1/webhooks/{webhook_id}/rotate-secret
Authorization: Bearer <access_token>
```

Generates a new `whsec_…` secret. Returns `200 OK`:

```json
{
  "secret": "whsec_new…",
  "secret_prefix": "whsec_abc…"
}
```

Old deliveries already in flight that use the previous secret will fail
verification on the customer's side and trigger their normal rejection
flow.

### Send test delivery

```http
POST /api/v1/webhooks/{webhook_id}/test
Authorization: Bearer <access_token>
```

Synthesises a payload, signs it, and POSTs it to the webhook URL. Returns
`200 OK`:

```json
{
  "success": true,
  "http_status_code": 200,
  "response_body": "<truncated body>"
}
```

`success` is `true` iff the HTTP status is in `[200, 300)`.

### List deliveries

```http
GET /api/v1/webhooks/{webhook_id}/deliveries?limit=50&offset=0
Authorization: Bearer <access_token>
```

Returns `200 OK`:

```json
{
  "items": [
    {
      "id": "uuid",
      "webhook_id": "uuid",
      "email_event_id": "uuid",
      "status": "delivered",       // pending | delivered | failed | dead_lettered
      "attempt_count": 1,
      "http_status_code": 200,
      "response_body": "…",
      "next_retry_at": null,
      "delivered_at": "…",
      "last_error": null,
      "created_at": "…",
      "updated_at": "…"
    }
  ],
  "limit": 50,
  "offset": 0
}
```

### Delete webhook

```http
DELETE /api/v1/webhooks/{webhook_id}
Authorization: Bearer <access_token>
```

Hard-deletes the webhook and cascades to its delivery log. Returns
`204 No Content`.

## Events

All routes require authentication. Mounted under `/api/v1/events`.

### List events

```http
GET /api/v1/events?mailbox_id=…&status=…&limit=50&offset=0
Authorization: Bearer <access_token>
```

Filters:

- `mailbox_id` — UUID of a mailbox owned by the caller
- `status` — one of `pending`, `delivered`, `failed`, `dead_lettered`

Returns `200 OK`:

```json
{
  "items": [
    {
      "id": "uuid",
      "mailbox_id": "uuid",
      "message_id": "<msg@example.com>",
      "imap_uid": "123",
      "sender_email": "user@example.com",
      "sender_name": "User",
      "recipients": ["you@example.com"],
      "subject": "Hello",
      "text_body": "…",
      "html_body": "<p>…</p>",
      "attachments_metadata": [{ "filename": "…", "content_type": "…", "size": 1234 }],
      "in_reply_to": null,
      "status": "delivered",
      "error_message": null,
      "attempt_count": 1,
      "received_at": "…",
      "processed_at": "…",
      "created_at": "…",
      "updated_at": "…"
    }
  ],
  "limit": 50,
  "offset": 0,
  "total": 137
}
```

### Get event

```http
GET /api/v1/events/{event_id}
Authorization: Bearer <access_token>
```

Returns a single `EmailEventResponse`.

### Retry event

```http
POST /api/v1/events/{event_id}/retry
Authorization: Bearer <access_token>
```

Re-enqueues webhook fan-out for an event in any status. Typically used after
manually fixing a destination URL or after a `dead_lettered` delivery.
Returns `202 Accepted`:

```json
{ "status": "queued" }
```

## Analytics

All routes require authentication. Mounted under `/api/v1/analytics`.

### Overview

```http
GET /api/v1/analytics/overview?days=7
Authorization: Bearer <access_token>
```

Returns aggregate KPIs for the past `days` (1–90, default 7): event counts,
delivery counts, success rate, and a few derived metrics.

### Top senders

```http
GET /api/v1/analytics/top-senders?days=7&limit=10
Authorization: Bearer <access_token>
```

Returns an array of `{ sender_email, count }` rows ordered by count desc.

### Daily volume

```http
GET /api/v1/analytics/volume?days=30
Authorization: Bearer <access_token>
```

Returns an array of `{ date, count }` rows (1–365 days).

### Webhook performance

```http
GET /api/v1/analytics/webhooks?days=7
Authorization: Bearer <access_token>
```

Returns an array of `{ webhook_id, name, total, delivered, failed, success_rate }`.

### Resource counts

```http
GET /api/v1/analytics/resources
Authorization: Bearer <access_token>
```

Returns the caller's mailbox and webhook counts (no time window):

```json
{
  "mailbox_count": 2,
  "webhook_count": 4
}
```

## Health

These endpoints are **unauthenticated**.

### Liveness

```http
GET /
```

```json
{ "status": "healthy", "service": "MailPulse" }
```

### Readiness

```http
GET /health/ready
```

Returns `200` if Postgres responds to `SELECT 1`, else `500`.

### System health (deep)

```http
GET /health/system
```

Probes Postgres, Redis, and reports queue stats:

```json
{
  "status": "healthy",
  "service": "MailPulse",
  "version": "1.0.0",
  "environment": "development",
  "checks": {
    "database": "connected",
    "redis": "connected",
    "queue": "ok"
  },
  "deliveries": {
    "pending": 3,
    "failed": 0,
    "dead_lettered": 0
  }
}
```

If any check fails, `status` becomes `degraded` and the failing entry holds
the error string.

## Errors

All errors share one shape:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Invalid request body"
  }
}
```

Common codes:

| HTTP | code                | When                                                            |
| ---- | ------------------- | --------------------------------------------------------------- |
| 400  | `validation_error`  | Pydantic validation failed on the request body or query params. |
| 401  | `authentication_error` | Missing or invalid access token.                              |
| 403  | `forbidden`         | Authenticated but not the owner of the resource.                |
| 404  | `not_found`         | Resource does not exist for this user.                          |
| 409  | `conflict`          | Resource already exists (e.g. email already registered).        |
| 422  | `unprocessable`     | Domain rule failed (e.g. mailbox health check).                 |
| 500  | `internal_error`    | Unhandled server error.                                         |

The exception layer is in `app/core/exceptions/`; extend it by subclassing
`MailPulseError` for new domain errors.

## End-to-end example

```bash
# 1. Register
ACCESS=$(curl -s -X POST http://localhost:8080/api/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"you@example.com","password":"supersecret123","full_name":"You"}' \
  | jq -r .access_token)

# 2. Add a mailbox
MAILBOX=$(curl -s -X POST http://localhost:8080/api/v1/mailboxes \
  -H "Authorization: Bearer $ACCESS" \
  -H "Content-Type: application/json" \
  -d '{"email_address":"me@gmail.com","password":"app-password","imap_host":"imap.gmail.com"}' \
  | jq -r .id)

# 3. Register a webhook
WEBHOOK=$(curl -s -X POST http://localhost:8080/api/v1/webhooks \
  -H "Authorization: Bearer $ACCESS" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://myapp.com/hooks/email","name":"My App"}')

echo "$WEBHOOK" | jq .secret         # save this — shown only once

# 4. Wait for the worker to poll, then inspect events
curl -s -H "Authorization: Bearer $ACCESS" \
  http://localhost:8080/api/v1/events | jq .
```

See [webhooks.md](webhooks.md) for the receiving-side verification example.
